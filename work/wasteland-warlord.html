Wasteland Warlord

A post-apocalyptic strategy RPG, and a study in turning a very large design into a structure that can be built by one person.

RoleSolo designer, developer
EngineUnity
DocsNotion GDD
StatusIn development
FocusSystems architecture

01Why a game is in this portfolio

Wasteland Warlord is a post-apocalyptic strategy RPG that I design and develop alone in Unity. It is here because it is the clearest example of how I think about systems: a game is a product where every rule touches every other rule, and the only way to keep it sane is architecture.

A huge design document is worthless until it becomes a structure you can build.

02Five engines

The game design document is large: factions, religions, economies, combat, clothing, music. I partitioned all of it into five engines with clear boundaries, so every new idea has exactly one home.

03One model for everything that changes a character

Statuses, conditions and traits usually grow into three tangled systems. Here they are one type: the Modifier. A wound, a faction trait and a slave mark all use the same structure, so they stack, expire and interact under the same rules.

  • Three health scales. Physical, mental and social, each from −20 to +20
  • Combat. A 15-rung attack ladder with range bands and sub-actions
  • Population. 24 character archetypes across hostile, neutral and settlement bands
  • Economy. Brass currency, relic cells and a six-axis item valuation model

The modifier pattern proved so useful that I extracted it into a reusable template for my other game projects.

04From document to running build

  • Working hex world map with fog of war, day cycle and resource drain
  • ScriptableObject architecture, so design data lives outside code
  • A six-layer view stack for the hex map
  • Art direction with eight visual pillars, a five-state day and night palette and a portrait system
  • Audio direction built on contrast: held breath while exploring, screams in combat, with morale shaping the tonality

05How AI fits

The design document lives in Notion and is written and audited with AI agents across separate workstreams (lore, systems, art, audio, Unity). A consistency audit across about 22 pages caught contradictions before they reached code. The same agents help write Unity editor tooling, so design changes reach the build without manual steps.
